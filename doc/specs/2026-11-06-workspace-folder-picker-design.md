# 工作区文件夹选择器

日期：2026-11-06
状态：已确认，待实现

## 背景

Web UI 的「添加工作区」现在只有一个手填路径的输入框（`static/index.html` 的 `#ws-dialog`），
加目录得自己去资源管理器抄路径。因为界面可能通过 `--web 0.0.0.0:8080` 远程使用，
不能调用系统原生文件对话框——那会弹在服务器那台机器的屏幕上。所以目录浏览必须走
HTTP 接口，由页面自己绘制。

浏览范围定为**全盘**：Windows 从盘符起，Unix 从 `/` 起。这个接口没有额外的访问控制，
和现有 Web UI「能连上就能让 agent 读写本机文件」的能力一致；默认仍然只监听
`127.0.0.1`，监听所有网卡时启动提示里的警告不变。

## 后端

### `GET /api/fs/list?path=<绝对路径>`

`path` 为空时是根列表：Windows 逐个探测 C:–Z: 里存在的盘符（标准库没有
`GetLogicalDrives`，不值得为此引依赖），Unix 返回 `/`。

响应：

```json
{
  "path": "D:\\code\\go",
  "parent": "D:\\code",
  "roots": false,
  "entries": [{"name": "agent-dev", "path": "D:\\code\\go\\agent-dev"}],
  "home": "C:\\Users\\CXJ",
  "work_dir": "D:\\code\\go\\agent-dev"
}
```

- 只返回**目录**；点开头的隐藏目录照常返回。
- 符号链接 / junction 指向目录时当成目录返回。
- 条目按名字排序（忽略大小写）。
- 根列表模式下 `path` 为空、`parent` 为空、`roots` 为 true。
- 路径不存在、不是目录、无权限读目录 → 400 + `{"error": "..."}`。
- 路径规范化：`filepath.Abs` + `Clean`；Windows 上单写 `C:` 补成 `C:\`，
  避免被当成「该盘的当前目录」。

### `POST /api/fs/mkdir`

请求 `{"path": "<父目录>", "name": "<新文件夹名>"}`，成功回 `{"path": "<新建目录>"}`。

- 名字去首尾空白后不能为空，不能是 `.` / `..`，不能含 `/` 或 `\`（也就是不能借机穿越）。
- 其余非法字符（Windows 的 `:*?"<>|`、保留名等）交给 `os.Mkdir` 报错。
- 已存在 → 400。

现有 `POST /api/workspaces` 不动：选好目录后仍由它登记工作区。

## 前端

把 `#ws-dialog` 改造成选择器，仍用原生 `<dialog>`：

- **地址栏**：显示当前目录，也可以手输/粘贴绝对路径后回车跳转（远程场景很实用）。
- **快捷按钮**：上一级、根目录、主目录。
- **列表**：一行一个子目录，点击进入；首行是「.. 上一级」；点开头的目录显示得淡一些；
  加载中 / 空目录 / 无权限各有提示。
- **新建文件夹**：展开一个输入行，回车调用 `POST /api/fs/mkdir`，成功后重新列当前目录。
  根列表模式下不允许新建（先进入某个盘符）。
- **选择此文件夹**：把当前所在目录交给 `POST /api/workspaces`，然后关闭弹窗、
  刷新工作区列表并切过去。根列表模式下按钮禁用。
- 打开弹窗时从当前工作区路径开始；没有就退回根列表。不记忆上次位置。

前端没有构建步骤，仍然只改 `static/app.js`、`static/index.html`、`static/style.css`
三个文件，靠 `go:embed` 打包。

## 错误处理

- 所有失败都以 400 + 中文 `error` 返回，前端直接把这句话摆在弹窗里。
- 列目录是只读操作，失败不影响已有工作区和正在跑的会话。
- 快速连点目录时用请求序号丢弃过期响应，避免后到的旧结果覆盖新目录。

## 测试

Go 侧新增接口测试（`src/webui`）：

- 临时目录树：子目录、隐藏目录、普通文件；验证文件被排除、排序正确、`parent` 正确。
- 不存在的路径、指向文件的路径 → 400。
- 根列表模式：`roots == true`，至少有一项。
- mkdir：新建成功；重名 → 400；`../x`、`a/b`、`.`、`..` → 400。
- 打开目录后子目录立即可见（新建 → 列表出现）。

前端没有 JS 测试基建，靠上述 HTTP 层测试 + 手工验证弹窗交互。
